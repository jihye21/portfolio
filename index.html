  • 실무자 관점 문제 정의: 현장 실무에서 발생하는 사용자(점주·직원·고객)의 문제점을 정확히 파악하는 능력 함양
  • 스마트 리테일 연계성: 현장의 흐름을 정확히 읽고 실무에 유용한 시스템을 기획·구현하는 능력 확보

  • fail2ban 보안 솔루션 적용: fail2ban 보안 솔루션 및 커스텀 filter 스크립트 적용을 통한 무차별 대입 공격 차단 및 서버 보안성 강화
  • 웹 서비스 편의성 및 업무 효율화: i18n 라이브러리 도입을 통한 글로벌 사용자 접근성 제고 및 CS 접수부터 메일 알림까지 이어지는 내부 업무 자동화 폼 설계

핵심 프로젝트

Java · Spring Boot · 결제 · Kafka · WebSocket

일정 추천 및 그룹 결제·복지 포인트 웹 시스템 (3인 팀 프로젝트)

[개요] 직원·사용자·사장님 멀티 페르소나 기반으로 실시간 주가 연동 복지 포인트, 그룹 실시간 채팅 그리고 PG 결제 시스템을 구현한 O2O 웹 애플리케이션 개발.

[본인 역할] 백엔드 개발 담당 (Apache Kafka 실시간 파이프라인, WebSocket 그룹 채팅, KG 이니시스 PG 결제 시스템 전담 구현)

[배경 및 문제점]
• Kafka 도입 배경: 복지 포인트에 게이미피케이션 요소를 결합하고자 했으며, 실시간으로 변동되는 삼성전자 주가 데이터를 지연 없이 안정적으로 처리하는 파이프라인이 필요했습니다.
• PG 연동 이슈: 결제 전후로 처리해야 할 부가 로직이 비대해지면서 빠른 응답이 요구되는 결제 프로세스에서 네트워크 타임아웃 및 세션 끊김 리스크가 발생했습니다.

[과제]
• Apache Kafka 기반의 비동기 주가 데이터 수신 및 직원 대상 실시간 포인트 지급 구조 설계
• 사용자 간 WebSocket 그룹 채팅 구현 및 인스타그램 API를 통한 트렌디 장소 탐색 연동
• Spring Boot 기반 일반/그룹 결제 및 쿠폰·포인트 복합 결제 로직 구현

[구현]
• 직원 기능: Apache Kafka를 활용해 실시간 주가 데이터를 수신하고 실시간 주가 가격에 맞춰 복지 포인트가 즉시 지급되도록 구현
• 사용자 기능: WebSocket을 활용한 실시간 그룹 채팅 및 인스타그램 API 연동을 통한 일정 추천 기능 개발
• 결제 시스템: Spring Boot 기반 일반/그룹 결제 및 쿠폰·포인트 복합 결제 로직 구현

[트러블슈팅 및 최적화]
• PG 네트워크 타임아웃 방어: 결제 흐름 중간에 개입되던 부가 로직들을 철저히 분리하고 결제에 소스코드를 최대한 경량화하여 응답 지연 및 세션 끊김 현상을 성공적으로 해소
• 외부 API 연동 제약 극복: 인스타그램 피드 데이터 호출 시 요구되는 페이스북 비즈니스 관리자 권한 제약 문제를 팀원 간 계정 연동 및 권한 프로세스 정립을 통해 해결

[성과] 네트워크 타임아웃 리스크를 사전에 차단하여 결제 성공률을 높이고 대용량 트래픽 처리 기반을 마련했습니다.

game_schedule

[배경] Google Apps Script를 DB로 활용하는 웹 서비스 환경에서 Fetch마다 발생하는 응답 지연으로 인해 사용자 체감 렌더링 속도가 저하되는 성능 한계 직면.

[과제] 원격 DB 호출 횟수를 최소화하고 빠른 초기 로딩 속도를 보장하기 위해 브라우저 스토리지와 원격 서버를 연동하는 효율적인 데이터 캐싱 및 동기화 파이프라인 설계.

[구현]

  • LocalStorage 기반 캐싱 레이어 구현: "getState()" 및 "getAllGroups()" 함수를 구현하여 최초 요청 시 원격 DB에서 데이터를 가져와 LocalStorage에 캐싱하고 이후 요청은 로컬 데이터를 우선 조회하도록 설계.
  • 방어적 데이터 파싱 및 예외 처리: 캐시 데이터 파싱 시 발생할 수 있는 에러를 방지하기 위해 try-catch 구문과 Array.isArray 유효성 검증 로직을 추가하여 시스템 안정성 확보.

[한계점 및 트러블슈팅]

  • 실시간 데이터 동기화 부재: 로컬 캐시를 우선 참조하는 구조적 특성상, 다른 환경에서 데이터가 변경되었을 때 실시간으로 반영되지 않고 수동 새로고침을 해야 최신 상태가 동기화되는 제약 존재.
  • 개선 인사이트: Polling이나 웹소켓 도입을 통한 실시간성 확보 또는 캐시 만료(TTL) 전략의 필요성 인지.

[결과] 불필요한 네트워크 I/O를 줄여 초기 페이지 로딩 속도를 개선하고 서버 장애나 네트워크 단절 시에도 예외 처리와 Fallback을 통해 서비스 중단을 방지하는 견고한 프론트엔드 데이터 흐름 구축.

wish_keyring

[배경] 모바일 환경에서 사용자의 몰입감을 높이기 위해 물리 엔진(Matter.js) 기반의 인터랙션 요소를 도입함. 단, 기기별 디바이스 센서(Gyroscope) 노이즈, 화면 회전(Screen Orientation)에 따른 좌표축 왜곡, 물리 엔진 중력 값 매핑 시 발생하는 모션 끊김 등의 기술적 한계 직면.

[과제] 센서 데이터를 정규화하고 화면 회전 각도에 따른 실시간 좌표계 보정 로직 구현. 물리 엔진(Gravity)과 CSS 3D Transform을 연동해 하드웨어 가속 기반의 부드러운 입체 인터랙션 파이프라인 구축.

[구현]

  • 센서 데이터 안정화 및 회전 대응: STABILIZE_THRESHOLD를 적용해 초기 센서 노이즈 필터링. window.screen.orientation으로 기기 회전 각도를 감지하고 beta/gamma 축을 동적으로 재매핑하여 일관된 기울기 제어 구현.
  • 물리 엔진 및 DOM 3D Sync: 보정된 틸트 값 기반으로 engine.world.gravity.x/y를 실시간 동기화. #keyring-box에 perspective(1000px) 및 3D Transform을 적용해 물리적 입체감 극대화.

[한계점 및 트러블슈팅]

  • 브라우저 세션 재시작 시 중력 역전 현상: 브라우저를 완전히 종료 후 재시작할 때, 모바일 OS 및 브라우저 보안 정책에 따른 초기 센서 이벤트 훅 시점 문제로 인해 물리 엔진의 중력 방향이 반대로 작용하는 이슈 확인.
  • 개선 방향: 센서 이벤트 리스너 등록 전 초기 기기 Pose의 기준 값을 보정하는 캘리브레이션 로직 추가 검토 필요성 인지.

[결과] 하드웨어 센서와 웹 물리 엔진을 유기적으로 결합하여 기기 조작에 즉각 반응하는 고도화된 인터랙티브 인터페이스 완성 및 모바일 웹 환경의 하드웨어 연동 제약 조건에 대한 깊은 이해 획득.
